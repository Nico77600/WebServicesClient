# Changelog — Web Services Client for Exchange

All notable changes are listed here. Versions follow MAJOR.MINOR.PATCH (see the guide, Annex D).
Author: Nicolas Fabert.

## [1.0.0] — 2026-10-06

First version (developed as *EWS OAuth Mailbox*): EWS for Exchange on-premises and **Microsoft Graph for Exchange Online**. A rewrite of `Test-EwsOAuthFreeBusy.ps1` (free/busy of one mailbox with an AD FS device code) into a toolbox with the structure and the standards of EAS OAuth Mailbox.

### Added
- **Two protocols**: `Target.Protocol` / `-Protocol` `Auto` (default: Microsoft Graph for a mailbox in Exchange Online, EWS on-premises), `EWS` or `Graph`. EWS is being retired in Exchange Online (disabled from October 2026, stopped in April 2027; HTTP 403 with `X-EWS-Policy-Reason`, now explained), and Graph does not reach on-premises mailboxes. With Graph the same scenarios use `mailFolders`, `childFolders`, `messages`, `sendMail`, `reply`, `move`, `DELETE` / `permanentDelete` and `calendar/getSchedule`; the token is requested for `https://graph.microsoft.com/.default` and *Token claims* names the permission the scenario lacks (`Mail.*`, `Calendars.*`, `.Shared` for delegate access, application roles). Discovery checks `graph.microsoft.com`, its challenge and a forged token. A **Protocol** check says which one is used and why; the stage titles, the report and the window follow it.
- **Free/busy views**: in the report, a scheduling-assistant view — a button per day with a small map, one row per mailbox with the calendar items (busy, tentative, out of office, working elsewhere; subject, location and times in a tooltip), working hours, current time and an **Everyone free** row with the common free time of the day; in the console, a map per mailbox and day, one cell per hour. The result keeps the merged view, the working days and hours and the window (`FreeBusyWindow`).
- **Test data**: `SeedData` fills a test mailbox (folders `Projects`, `Projects\Migration`, `Archive 2026`; six messages, one filed; seven calendar items over five working days: busy, tentative, out of office, working elsewhere), `CleanData` removes them; EWS or Graph, nothing created twice.
- **Folders tab**: the real name of each folder, indented as a tree (parents before children); the full path and the IDs in the details and in `Folders.csv` (with `Depth`).
- **Working hours in the time zone of the mailbox**: the UTC offset of the zone EWS returns (bias and daylight-saving rules) or Graph names is applied to the hatched cells and to the *Everyone free* row, and shown next to the hours.
- **Four ways to sign in**: OAuth with **AD FS** (Exchange Server 2019 CU13+ / SE), OAuth with **Entra ID** (on-premises with hybrid modern authentication, or **Exchange Online**), **Basic**, and **Windows** (`Negotiate`, `NTLM`, `Kerberos`; current Windows account or `-Credential`).
- **Three contexts** with OAuth: **User** (Microsoft public client), **Delegated** (your application on behalf of the user, `EWS.AccessAsUser.All`, optional client secret, own redirect URI) and **Application** (client credentials with a certificate — signed assertion — or a client secret; role `full_access_as_app`).
- **Access to the mailbox**: own mailbox, **delegate** access (`-SignInUser`, `<t:Mailbox>` in the folder IDs, Send As / Send on Behalf) or **impersonation** (`ExchangeImpersonation`), chosen automatically from the context.
- **Discovery of EWS**: **Autodiscover** like Outlook (v2 JSON on `autodiscover.<domain>`, `<domain>` and Exchange Online; classic POX with Basic or Windows, HTTP redirect method and SRV record; the typed URL as a last resort) or **Manual**.
- **Operations**: list the folders (`FindFolder` deep, paths), create the test folder, read the latest messages and one in full, send a test message and wait for its delivery, reply to a given message, move, delete (`MoveToDeletedItems`, `SoftDelete`, `HardDelete`), free/busy of one or several mailboxes. Scenarios `Discovery`, `SignIn`, `Endpoint`, `Folders`, `ReadMail`, `FreeBusy`, `CreateFolder`, `SendMail`, `ReplyMail`, `MoveMail`, `DeleteMail`, `ReadOnly`, `MailCycle`, `Full`. Writes need `-AllowWrite`; reply, move and delete work only on `-ItemId`, `-ItemSubject` or the test message of the tool.
- **EWS good practices**: `X-AnchorMailbox`, `X-PreferServerAffinity` and affinity cookies sent back, `client-request-id` / `return-client-request-id`, own `User-Agent`, `RequestServerVersion`, gzip, throttling (`ErrorServerBusy` with `BackOffMilliseconds`, HTTP 429/503 with `Retry-After`, at most `Ews.MaxRetries` attempts and 60 s).
- **Traceability**: every request and response in the report (SOAP indented, JSON, HTML summarised), the EWS operation, the Exchange servers that answered (`X-FEServer`, `X-BEServer`, `X-CalculatedBETarget`), the request ID. Windows: the handshake is done by the tool (`NegotiateAuthentication`), every leg traced, NTLM messages and SPNEGO decoded (server, NetBIOS and DNS domain, Windows version; user, domain and workstation) — never the response to the challenge nor the Kerberos ticket. Affinity cookies shown, other cookies masked.
- **Extended Protection**: every Windows handshake carries the channel binding token of the TLS connection (`tls-server-end-point`, RFC 5929), like Windows and Outlook, shown in the trace with the SPN: NTLM works with Extended Protection set to *Require* and behind a reverse proxy that terminates TLS (without it the domain controller refuses the logon, status `0xC000035B`).
- *Discovery* without sign-in: TLS certificate (interrupted handshake told apart from an untrusted certificate), authentication offered by EWS, AD FS metadata, Entra ID tenant and user realm, OAuth offered to the mailbox, tenant trusted by Exchange, forged token refused, wrong password refused with a user that does not exist, NTLM challenge without credentials, Kerberos realm (SRV record, port 88, domain membership).
- Console, daily log, CSV (`Steps`, `Folders`, `Messages`, `FreeBusy`, `Actions`, `Trace`), `Summary.json` and a self-contained HTML report; WPF window (`-Gui`, Fluent theme) with four sign-in cards, the context and the options of the scenario.
- 40 Pester tests against a simulated Exchange, AD FS, Entra ID and Microsoft Graph (NTLM type 2 built byte by byte).
- Documentation: a **user guide** (prerequisites and everyday commands) and a **developer guide** (how it works, sign-in methods and their configuration, report and HTTP trace, troubleshooting, architecture), in Markdown and as self-contained HTML; screenshots rendered by the tool itself against the simulated Exchange (`tools\New-DocumentationImages.ps1`), README graphics in light and dark (`tools\New-ReadmeImages.ps1`).

### Fixed (before release)
- Folder paths looped (`\Contacts\GAL Contacts\Contacts\...`): EWS and Graph folder IDs are case-sensitive base64, they were indexed in a case-insensitive hashtable. An ordinal dictionary is used, with a guard against cycles.
- *Working elsewhere* missing from the free/busy maps: Exchange counts it as free in the merged view; the calendar items now complete the view.

### Validated
- Exchange Server SE in hybrid with HMA (four servers, a DAG, published through an IIS ARR reverse proxy): *ReadOnly* through EWS with an Entra ID token (front-end and back-end servers named, affinity cookie, folders, free/busy); *ReadOnly* with **Windows NTLM from a computer outside the domain**, through the reverse proxy (channel binding required); *SeedData*; working hours in the time zone of the mailbox.
- Exchange Online: *Full* through Microsoft Graph (folders, messages, free/busy, test folder, sendMail and delivery, reply, move, delete), *SeedData* and *ReadOnly*; the same mailbox through EWS: HTTP 403 `EWS is blocked by policy for this user or tenant`.
- Without sign-in: Exchange Online (Autodiscover v2, OAuth challenge, trusted issuers `@*`, forged token refused; Basic refused), Exchange SE with HMA (Autodiscover, tenant, OAuth for the mailbox, NTLM challenge naming the mailbox server and the AD domain, Kerberos realm out of reach from outside the domain), an AD FS organisation (Autodiscover not published; TLS handshake interrupted on the path).
